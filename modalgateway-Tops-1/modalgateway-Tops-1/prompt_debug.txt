Wide Retrieval RAG Strategy

 This document outlines the implementation of **Wide Retrieval** for the TalentOps chatbot. This strategy allows the system to answer global questions (e.g., "Summarize the project") by dynamically expanding the context window when broad queries are detected.

 Overview

 Current RAG systems often fail on broad queries because they only retrieve a small number of snippets (Top-K). Wide Retrieval solves this by fetching a significantly larger number of chunks when the user's intent is broad, leveraging the large context window of modern LLMs (like Llama 3.1 8B's 128k window).

 Implementation Details

 The implementation involves modifying the [rag-backend/server.py](file:///d:/chatbot/AkashWork/modalgateway-Tops-1/modalgateway-Tops-1/rag-backend/server.py) to detect broad intent and adjust the `match_count` parameter sent to Supabase.

 1. Intent Detection Keywords

 We define a set of keywords that typically indicate a request for global information:

 - `explain`

 - `overview`

 - `goal`

 - `summary`

 - `project`

 - `whole`

 2. Dynamic Count Logic

 - **Standard Query**: 5 chunks (~2,500 words).

 - **Broad Query**: 40 chunks (~20,000 words).

 3. Proposed Code Change

 Modify the [query_rag](file:///d:/chatbot/AkashWork/modalgateway-Tops-1/modalgateway-Tops-1/rag-backend/server.py#237-302) function in [d:\chatbot\AkashWork\modalgateway-Tops-1\modalgateway-Tops-1\rag-backend\server.py](file:///d:/chatbot/AkashWork/modalgateway-Tops-1/modalgateway-Tops-1/rag-backend/server.py):

 ```python

 # Before

 params = {

 "query_embedding": q_emb,

 "match_threshold": 0.50,

 "match_count": 5,

 "filter": filters

 }

 # After

 broad_keywords = ["explain", "overview", "goal", "summary", "project", "whole"]

 is_broad = any(kw in req.question.lower() for kw in broad_keywords)

 count = 40 if is_broad else 5

 params = {

 "query_embedding": q_emb,

 "match_threshold": 0.50,

 "match_count": count,

 "filter": filters

 }

 ```

 Benefits

 - **Zero Infrastructure Change**: No new database tables or ingestion pipelines.

 - **Improved Accuracy**: Provides the LLM with enough context to form a complete picture of the project.

 - **Low Latency**: Fetching 40 vectors from Supabase is still extremely fast, and the LLM handles the expanded context efficiently.
